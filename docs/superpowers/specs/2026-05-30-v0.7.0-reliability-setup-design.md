## 1. Config Zero-Value Fix (Issue #22)

**Problem:** JavaScript's `||` operator treats `0` as falsy. Any numeric config field saved as `0` (e.g. `RecentWatchBoost = 0` to disable emphasis) is silently reset to its hardcoded default on the next page load, and subsequently overwritten on save.

**Fix:** Replace every `config.X || default` expression in the `loadConfiguration` handler in `configPage.html` with `config.X ?? default`. The nullish coalescing operator (`??`) only falls back when the value is `null` or `undefined` — not `0`.

**Fields affected:**
- `FavoriteBoost`
- `RecentWatchBoost`
- `RecencyDecayHalfLifeDays`
- `MinWatchedItemsForPersonalization`
- `MovieRecommendationCount`
- `TvRecommendationCount`
- `ActorVocabLimit`
- `TagVocabLimit`
- `RatingProximityWeight`
- `AbandonedSeriesThresholdDays`

**Files:** `Configuration/configPage.html` only.

## 2. Auto-Scan After Refresh

**Problem:** After symlinks are written, users must manually scan their recommendation libraries to see updated recommendations. The current `LogLibraryScanInstructions()` method logs a reminder, but many users miss it.

**Fix:** After all users' symlinks have been synced in `RecommendationRefreshTask.ExecuteAsync`, call:

```csharp
_libraryManager.QueueLibraryScan();
```

`QueueLibraryScan()` is a void, non-blocking method with an explicit Jellyfin source comment: *"This exists so plugins can trigger a library scan."* It is the correct API for plugin-initiated scans. The call is placed *after* the existing 2-second file-system flush delay (already in `RecommendationRefreshTask`) so symlinks are fully visible before the scan begins. The `LogLibraryScanInstructions()` method and its call site are removed.

**Trade-off:** Scans all libraries, not just recommendation libraries. This is acceptable — it is identical to what users do today manually, and Jellyfin's incremental scanner is fast for libraries with no real changes.

**Files:** `ScheduledTasks/RecommendationRefreshTask.cs`, inject `ILibraryManager`. Note: `ILibraryManager` is already available in `RecommendationRefreshTask` via the existing `VirtualLibraryManager` dependency — inject it directly into the task constructor.

## 3. Embedding Cache

**Problem:** Every refresh recomputes TF-IDF embeddings and vocabulary from scratch, even when the library hasn't changed. On a server restart followed by an immediate refresh, the full computation (30+ seconds for 2000 items) is redundant.

### Cache File

Stored at `{plugin-data}/cache/embeddings-cache.json`. Written after every successful refresh; loaded at the start of the next refresh.

```json
{
  "version": 1,
  "fingerprint": "<sha256-hex>",
  "itemCount": 1847,
  "computedAt": "2026-05-30T04:00:00Z",
  "vocabulary": { "...FeatureVocabulary fields..." },
  "embeddings": {
    "<item-guid>": { "vector": [0.12, -0.04, "..."] }
  }
}
```

Float arrays are stored as plain JSON arrays. At ~1400 dimensions × 2000 items the file is approximately 25–30 MB — fast to read from any SSD.

### Library Fingerprint

A SHA-256 hash of the sorted list of `(ItemId.ToString(), DateModified.Ticks.ToString())` pairs for every item currently in the library. Catches additions, deletions, and metadata changes.

### Refresh Flow

1. Compute fingerprint from current library items.
2. If cache file exists and `fingerprint` matches → load embeddings + vocabulary, skip computation. Log: `"Using cached embeddings ({N} items)"`.
3. If fingerprint mismatches or cache absent/corrupt → compute from scratch, save new cache. Log: `"Recomputed embeddings ({N} items)"`.
4. Any cache read/write error → proceed without cache, log warning (non-fatal; refresh continues normally).

### New Component

`EmbeddingCacheService` — standalone service responsible for fingerprinting, reading, writing, and validating the cache file. Injected into `RecommendationRefreshService`. Keeps cache logic fully separate from orchestration and embedding computation.

**Files:**
- `Services/EmbeddingCacheService.cs` (new)
- `Services/RecommendationRefreshService.cs` (inject + call `EmbeddingCacheService`)
- `PluginServiceRegistrator.cs` (register `EmbeddingCacheService` as singleton)

Note: `System.Security.Cryptography.SHA256` is a standard .NET 9 BCL type — no additional package reference needed.

## 4. Per-User Error Isolation

**Problem:** In `RecommendationRefreshService.GenerateRecommendationsForMultipleUsersAsync`, a failure during one user's profile build or recommendation generation can abort the entire refresh, leaving all remaining users without updated recommendations.

**Fix:** Wrap each user's pipeline execution in a try-catch. Collect per-user errors into a `List<(Guid UserId, Exception Error)>`. Continue to the next user on failure. Return both the successful recommendations and the error list to the caller.

The task-level sync loop in `RecommendationRefreshTask` already has per-user error handling — this extends the same pattern to the earlier pipeline stage.

**Files:** `Services/RecommendationRefreshService.cs`.

## 5. Diagnostics / Last-Refresh Status

### Persisted Result File

After each refresh completes (success or partial), write `{plugin-data}/last-refresh.json`:

```json
{
  "completedAt": "2026-05-30T04:00:45Z",
  "durationSeconds": 43.2,
  "totalUsers": 3,
  "successfulUsers": 3,
  "failedUsers": [],
  "totalLibraryItems": 1847,
  "embeddingsCached": true,
  "errors": []
}
```

`failedUsers` is an array of `{ "userId": "<guid>", "username": "...", "error": "..." }` objects.

### API Endpoint

`GET /LocalRecs/RefreshStatus` — reads and returns `last-refresh.json`. Returns `404` if no refresh has run yet. Lightweight; no Jellyfin service calls.

**Controller:** `Api/RefreshStatusController.cs` (new). Jellyfin auto-discovers controllers from the plugin assembly — no registration in `PluginServiceRegistrator` required.

### Config UI

The Settings tab in `configPage.html` gets a read-only **Last Refresh** block at the top, populated on page load. Displays:
- Time since last refresh (e.g. "6 hours ago")
- Duration
- Users: `3/3 successful` or `2/3 — 1 failed: [username]`
- Whether embeddings were served from cache
- Any error messages

No polling — static snapshot loaded once when the page opens.

**Files:**
- `Api/RefreshStatusController.cs` (new)
- `Services/RecommendationRefreshService.cs` (write result file)
- `Configuration/configPage.html` (status block)

## 6. Setup UI Checklist

**Problem:** The current Setup Guide tab lists paths with copy buttons but gives no feedback on whether setup is complete. Admins have no way to tell at a glance whether libraries are correctly linked.

### New Endpoint

`GET /LocalRecs/SetupStatus` — checks each user's virtual library directories and cross-references `ILibraryManager.GetVirtualFolders()` to determine whether Jellyfin has a library pointing at each path. Returns:

```json
{
  "users": [
    {
      "userId": "<guid>",
      "username": "John",
      "directoriesExist": true,
      "moviesPath": "/data/plugins/.../john/movies",
      "moviesLibraryLinked": true,
      "tvPath": "/data/plugins/.../john/tv",
      "tvLibraryLinked": false
    }
  ],
  "isWindows": false
}
```

**Controller:** `Api/SetupStatusController.cs` (new). Jellyfin auto-discovers controllers — no registration in `PluginServiceRegistrator` required. Uses the same pattern as `LibraryPathsController` (already calls `GetVirtualFolders()` with `vf.Locations` on line 66-70).

### Config UI — Setup Tab Redesign

The Setup tab is rewritten as a status-aware numbered checklist, loaded dynamically from `SetupStatus`. Per user:

```
John
  ✅ Plugin directories created
  ✅ Movies library linked        /data/plugins/.../john/movies
  ❌ TV library not linked        [Copy Path]  [Add Library →]
```

**"Add Library →"** links directly to Jellyfin's Add Library page in the web UI.

**Windows symlink warning:** If `isWindows: true` and any user's directories exist but appear empty (no symlinks), show the Developer Mode / Administrator notice inline — no log-digging required.

**Files:**
- `Api/SetupStatusController.cs` (new)
- `Configuration/configPage.html` (setup tab rewrite)
