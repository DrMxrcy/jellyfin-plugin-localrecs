# v0.8.0 Design: Negative Feedback & Per-User Genre Weights

## Overview

Give each Jellyfin user two controls over their recommendations:

1. **Item exclusions** — explicitly exclude specific movies or TV shows from ever appearing in their recommendations.
2. **Genre weights** — boost or suppress recommendations from specific genres (per user, not global).

Both are managed through a new user-facing plugin page and a set of `[Authorize]`-gated API endpoints. No admin elevation required — any logged-in Jellyfin user can manage their own preferences.

---

## Data Model

### `UserPreferences`

Stored at: `{Plugin.DataFolderPath}/users/{userId}/preferences.json`

```json
{
  "excludedItemIds": ["<guid>", "<guid>"],
  "genreWeights": {
    "Action": 1.5,
    "Horror": 0.2,
    "Comedy": 1.0
  }
}
```

- `excludedItemIds`: Set of Jellyfin item GUIDs the user never wants recommended.
- `genreWeights`: Float multipliers per genre. Absent genres default to `1.0`. Valid range: `0.0–3.0` (stored as-is, but clamped to `[0.1, 3.0]` at scoring time — weight `0.0` ranks the genre near the bottom, not fully blocked; use exclusions for hard blocks). `3.0` triples the score contribution.

## Components

### `UserPreferences` model (`Models/UserPreferences.cs`)

```csharp
public class UserPreferences {
    public HashSet<Guid> ExcludedItemIds { get; set; } = new();
    public Dictionary<string, float> GenreWeights { get; set; } = new();
}
```

### `UserPreferencesService` (`Services/UserPreferencesService.cs`)

Singleton. Owns in-memory cache and disk persistence.

```
ConcurrentDictionary<Guid, UserPreferences> _cache
```

- `GetPreferences(userId)` — returns cached entry or loads from disk; returns empty `UserPreferences` if file absent.
- `SavePreferences(userId, prefs)` — writes to `_cache` and serializes to disk immediately.
- Cache is never explicitly invalidated — writes always update both cache and disk atomically (overwrite file).
- Thread-safe: lock per user ID during write; reads are lock-free from `ConcurrentDictionary`.

Registered as singleton in `PluginServiceRegistrator`.

### `PreferencesController` (`Api/PreferencesController.cs`)

`[Route("LocalRecs/Preferences")]`, `[Authorize]` (not RequiresElevation).

Reads calling user's Jellyfin user ID from `HttpContext.User` claims.

| Endpoint | Method | Description |
|----------|--------|-------------|
| `GET /LocalRecs/Preferences` | Returns full preferences for calling user |
| `POST /LocalRecs/Preferences/Exclusions` | Body: `{ "itemId": "<guid>" }` — adds to exclusion set |
| `DELETE /LocalRecs/Preferences/Exclusions/{itemId}` | Removes from exclusion set |
| `PUT /LocalRecs/Preferences/GenreWeights` | Body: `{ "weights": { "Action": 1.5 } }` — replaces all weights |

All endpoints return `200 OK` with updated preferences, or `400 Bad Request` on invalid input.

### `userPreferences.html` (plugin page)

Second plugin page bundled in the DLL. User-accessible (not admin-only).

**Sections:**

1. **Excluded Items**
   - Search box → calls Jellyfin `/Items?searchTerm=...&IncludeItemTypes=Movie,Series&Limit=10` → shows results as clickable rows (poster + title)
   - Clicking a result calls `POST /LocalRecs/Preferences/Exclusions`
   - Current exclusion list shown below with remove (×) buttons per item
   - Item names fetched via `/Items/{id}` when loading the page

2. **Genre Weights**
   - Fetches genres from `/Genres?userId=...` filtered to genres present in user's library
   - Shows each genre as a labeled range slider (0.0 – 3.0, step 0.1, default 1.0)
   - "Save Genre Weights" button calls `PUT /LocalRecs/Preferences/GenreWeights`
   - Genres with weight 1.0 (unchanged) are omitted from the saved payload to keep storage lean

All JS follows the existing security constraint: no `innerHTML` for dynamic content — use `createElement`/`textContent`/`appendChild`.

### `RecommendationEngine` changes (`Services/RecommendationEngine.cs`)

**`GetUnwatchedCandidates(userId, config, ...)`**

Load `UserPreferencesService.GetPreferences(userId)` once per call. After the existing watched/access filters, add:

```csharp
if (prefs.ExcludedItemIds.Contains(item.Id)) continue;
```

**`ScoreCandidate(candidate, ...)`**

After computing `finalScore`, apply genre multipliers:

```csharp
float genreMultiplier = 1.0f;
foreach (var genre in candidate.Genres)
{
    if (prefs.GenreWeights.TryGetValue(genre, out var w))
        genreMultiplier *= w;
}
genreMultiplier = Math.Clamp(genreMultiplier, 0.1f, 3.0f);
finalScore *= genreMultiplier;
```

Clamp floor at `0.1` (not `0.0`) so an item with weight `0` can still appear — just ranked last. Items the user explicitly excluded are already filtered out before scoring.

`UserPreferences` is passed into `ScoreCandidate` from the caller (`GenerateRecommendations`), loaded once per user per recommendation run.

## Registration

`PluginServiceRegistrator` adds:

```csharp
serviceCollection.AddSingleton<UserPreferencesService>();
```

`PreferencesController` is auto-discovered by Jellyfin's ASP.NET Core pipeline (same as existing controllers).

`userPreferences.html` is registered in `Plugin.cs` alongside the existing `configPage.html`.

---

## Error Handling

- Missing preferences file → treat as empty preferences (no exclusions, all weights 1.0).
- Corrupt JSON → log warning, return empty preferences (non-fatal).
- `PUT /GenreWeights` with a weight outside `[0.0, 3.0]` → clamp silently before saving.
- `POST /Exclusions` with an item ID that doesn't exist in Jellyfin → accepted anyway (item may have been deleted; the ID just won't match anything).

## Release Automation (CI/CD)

Tag-triggered GitHub Actions workflow that builds, tests, packages, updates the manifest, and publishes a GitHub Release — all automatically when a semver tag is pushed.

### Trigger

```
push:
  tags: ['v*.*.*']
```

### New files

| File | Purpose |
|------|---------|
| `.github/workflows/release.yml` | Release workflow |
| `scripts/update-manifest.py` | Prepends new version entry to `manifest.json` |
| `RELEASE_NOTES.md` | Developer writes this before tagging; used as the release body and `changelog` field in manifest |

### Workflow steps

1. **Extract version** from tag: `v0.8.0` → `version=0.8.0`, `version_full=0.8.0.0`
2. **Build** — `dotnet build -c Release -p:Version=0.8.0.0 -p:AssemblyVersion=0.8.0.0 -p:FileVersion=0.8.0.0` (version comes from tag, not csproj)
3. **Test** — `dotnet test -c Release --no-build`; release aborts if tests fail
4. **Package** — zip `Jellyfin.Plugin.LocalRecs.dll` (paths stripped) as `jellyfin-plugin-localrecs-v0.8.0.zip`; compute MD5 checksum
5. **Update manifest.json** — `python3 scripts/update-manifest.py --version 0.8.0.0 --checksum $MD5 --tag v0.8.0`; also bumps `<Version>` in csproj
6. **Commit & push** — commits `manifest.json` + csproj back to `main` via `GITHUB_TOKEN` (requires `permissions: contents: write`)
7. **Create GitHub Release** — `gh release create v0.8.0 jellyfin-plugin-localrecs-v0.8.0.zip --title "v0.8.0" --notes-file RELEASE_NOTES.md --latest`

### `scripts/update-manifest.py` logic

- Reads `RELEASE_NOTES.md` for the `changelog` value
- Detects GitHub repo from `git remote get-url origin`
- Constructs `sourceUrl` as `https://github.com/{repo}/releases/download/{tag}/jellyfin-plugin-localrecs-{tag}.zip`
- Prepends new entry to `manifest[0].versions`; writes back with 2-space indent

### Developer release workflow

```bash
# 1. Write release notes
echo "..." > RELEASE_NOTES.md
git add RELEASE_NOTES.md
git commit -m "chore: prepare v0.8.0 release notes"

# 2. Push tag → Actions does everything else
git tag v0.8.0
git push origin v0.8.0
```

- Bulk import/export of preferences

- Per-user recommendation count overrides
